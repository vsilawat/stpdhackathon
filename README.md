# ASME-CIE Student Hackathon 2026 — Problem 1

CNC process-plan prediction from B-Rep CAD. We treated the problem as **recovering the
deterministic planning rules of the CAM generator** that produced the dataset, not as black-box
label prediction: B-Rep feature recognition → rule-based process planning → analytic
in-process-workpiece solids → generative G-code emission. Learned models appear only where mined
rules leave genuine ambiguity. Full write-up in [METHODS.md](METHODS.md).

## Results (disjoint holdout, every 5th part)

| Track | Points | Result |
|---|---|---|
| Easy — operation sequence | 20 | mean normalized Levenshtein **0.098**, set-F1 **0.955**, exact sequence 70.2% |
| Medium — IPW solids | 35 | mean IoU **0.996**, 77% of ops in the top rubric band |
| Hard — tools | 20 | positional tool type 84.9%, diameter within 2%: 78.1% |
| Hard — toolpaths (.ptp) | 25 | mined post-processor grammar; swept-volume IoU **0.83** (200-part sample) |

All four tracks × 10,000 parts pass the organizers' `validate_submission.py` with zero errors,
generated by one deterministic pipeline in about six minutes.

## Quick start

```bash
python3.12 -m venv .venv
.venv/bin/pip install -e .

# regenerate the graded test-set submission
.venv/bin/python scripts/generate_submission.py --data=data/test30 --out=test_submission --force

# regenerate all 10k training parts + holdout scores
.venv/bin/python scripts/generate_submission.py --force
.venv/bin/python scripts/score_easy.py
.venv/bin/python scripts/score_tools.py
.venv/bin/python scripts/score_medium.py
.venv/bin/python scripts/score_ptp.py
```

To reproduce the whole pipeline from scratch (mine the rules, retrain the models), follow the
ordered command list in [scripts/README.md](scripts/README.md).

## Large trained models

Four trained pickles exceed GitHub's 100 MB file limit and live as
[release assets](../../releases) instead of in the tree: `chain_tree.pkl` (157 MB),
`chain_tree12.pkl` (126 MB), `tool_dia_models.pkl` (672 MB), `pocket_tool_model.pkl` (466 MB).
Download them into `derived/` for full accuracy. **Without them the pipeline still runs** — every
loader falls back to the mined rules (`hole_chain`, catalog rules), just at lower accuracy. The
committed `submission/` and `test_submission/` files were generated with all models present.

The 4.9 GB dataset zip is likewise not committed; the extracted dataset is in `data/`, and the
Zenodo DOI above is the canonical source.
