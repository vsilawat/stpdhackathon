# submission/ — the competition deliverable

Generated by `scripts/export_easy.py` and `scripts/export_hard.py`.
**All 20,000 files pass the organizers' `validate_submission.py`.**

```
submission/
  easy/   10,000 x <part_id>_sequence.json    operation sequence
  hard/   10,000 x <part_id>_tools.json       tool type + diameter per operation
```

## Formats

Both schemas are fixed by the organizers' validator, which requires **exact**
key sets — extra fields are an error, not just missing ones — and operation
numbering starting at **1**.

**Easy** (`<part_id>_sequence.json`):

```json
{
  "part_id": "featured_part_00001",
  "summary": {"number_of_operations": 8},
  "operations": [
    {"operation_number": 1, "o1": "hole_making", "o2": "SPOT_DRILLING"}
  ]
}
```

`o1` ∈ {hole_making, mill_contour, mill_planar, OTHER};
`o2` ∈ {DRILLING, SPOT_DRILLING, DEEP_HOLE_DRILLING, HOLE_MILLING,
BORING_REAMING, AREA_MILL, FLOOR_WALL, OTHER}.

**Hard** (`<part_id>_tools.json`):

```json
{
  "part_id": "featured_part_00001",
  "summary": {"number_of_operations": 8},
  "operations": [
    {"operation_number": 1, "tool_type": "chamfer_mill", "tool_diameter_mm": 20.0}
  ]
}
```

`tool_type` ∈ {chamfer_mill, twist_drill, end_mill, spot_drill, insert_drill,
gun_drill, spade_drill, boring_tool}.

The two tracks are mutually consistent: every part has the same operation count
in both, so they describe one plan.

## Not submitted

- **Medium** (35 pts, IPW meshes) and the **Hard G-code** half (25 pts) are not
  attempted. Both are scored on volumetric overlap with a hard floor below
  which they score zero, and both need pocket *boundary* extraction, which we
  did not build. 82% of all material removed is pockets and slots and only 9%
  is drilling, so a drilling-only attempt would have scored zero. That
  measurement is why the tracks were skipped rather than half-attempted.

## Validating and scoring

```bash
git clone https://github.com/athulcd/ASME-CIE-Student-Hackathon-2026-Problem-1.git reference
python3 scripts/score_official.py   # runs their validator on all files, then scores Easy
python3 scripts/score_hard.py       # scores Hard tool selection
```

Current scores on the 2,000 held-out parts: Easy **14/20**
(edit distance 0.204, F1 0.932); Hard tool selection **~10/20**
(type correct 64.4%; when correct, median diameter error 0.00%).
